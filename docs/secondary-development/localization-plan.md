# 第一阶段：中文界面

日期：2026-11-03。状态：登录页样例后，用户已授权继续改造其他页面。本轮全站接入与账号验证码邮件翻译已实施；代码覆盖、自动验证及待完成的实际业务验收见 [实施记录](localization-implementation.md)。

用户明确中文界面应首先推进。将首期 F09 提到第一个交付阶段；模型销售计价、成本核算、禁止 BYOK、管理后台扩展和公网部署按各自后续方案推进。2026-11-06 已取消个人独立人民币余额及新增卡密商业改造，现有组织钱包和兑换卡继续复用。

## 1. 目标与默认规则

- 现有界面默认使用简体中文，支持切换英文。
- 未保存过语言选择时默认中文，不因浏览器为英文而自动切为英文。
- 用户主动切换后，当前浏览器保留选择；刷新、页面跳转及直接打开子页面一致，暂不做账号跨设备同步。
- 2026-11-08 用户明确登录页不需要语言切换入口；登录页沿用已保存语言及默认中文规则，不把缺少该入口列为待修问题。
- 页面首屏与客户端语言一致；页面语言标识、表单提示和必要无障碍说明随界面语言同步。
- 现有账号相关邮件已确认纳入第一阶段，主题及正文等文案随发起操作时的界面语言发送；未选择时默认中文，异步发送沿用发起时的语言。
- 复用现有页面和交互布局，翻译资源集中管理，为后续二开页面提供统一接入方式。

本文件描述交付要求。具体开源方案比较、建议选型、接入边界和开发批次见 [i18n 开发计划](i18n-development-plan.md)；登录页样例已采用 i18next + react-i18next，其他页面及完整环境兼容性仍需按批次验证。

## 2. 页面覆盖与建议顺序

| 顺序       | 页面或交付范围               | 需要覆盖的文案                                                                               |
| ---------- | ---------------------------- | -------------------------------------------------------------------------------------------- |
| 1          | 全局布局、登录与现有账号邮件 | 导航、侧栏、用户菜单、面包屑、登录与验证码、语言切换入口；现有账号邮件主题、正文及按钮等文案 |
| 2          | 主要创作流程                 | 首页、工作台、项目/序列、剧本、场景与分镜、图片/视频操作、角色/地点/风格、生成状态和操作提示 |
| 3          | 模型、设置与现有余额页面     | 模型筛选及规格标签、设置项、余额与交易、礼品码兑换、现有相关弹窗和说明                       |
| 4          | 现有管理页面                 | 用量、审核及相关已有操作的界面文案；不借翻译新增商业后台功能                                 |
| 贯穿各页面 | 动态与辅助信息               | 空状态、加载、确认、警告、表单校验、成功/失败提示、错误页、日期时间、按钮及必要无障碍文字    |

用户正常可达页面及现有账号邮件模板需列出覆盖清单，记录翻译完成和未覆盖项。公开文档、法律条款、供应商返回的模型介绍等长文本逐项盘点，不能因主要界面翻译完毕而声称这些内容均已完成。

账号邮件以实际已存在的发送场景和模板为准，覆盖主题、正文、按钮及已有预览文字等文案，不新增邮件类型；验证码、链接和认证行为保持原有语义。其他邮件及 CLI/MCP 文案单独列入后续范围。

新页面尚未实现时不制作假页面来充数；后续真实二开页面复用本阶段的翻译机制。

## 3. 翻译边界

本节约束界面翻译。2026-11-07 用户另行授权的系统指令双语改造见 [中英文系统指令](system-prompt-localization.md)；它按请求语言选择系统模板，不翻译既有用户内容或供应商协议。

- 用户输入、剧本、模型提示词、生成内容和用户命名保持原文。
- 模型名、供应商名、必要技术标识可保留原名；普通英文交互提示不能当作专有名词跳过。
- 给用户的常见错误提供可理解的中文/英文提示；技术日志和原始供应商诊断保持可追溯，不能把任意异常字符串替换当成完整国际化。
- 金额按现有数据的真实币种展示。本阶段不修改余额、卡密金额、价格、账本或汇率，不能把美元符号换成人民币来假装完成人民币改造。
- 只做翻译和语言切换，现有充值、模型、凭证、权限等行为不因本阶段改变；后续商业规则改造另行实施。

| 编号 | 检查场景                                                 | 预期结果                                                                                                                                                            |
| ---- | -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| L01  | 新浏览器或没有保存语言选择                               | 默认简体中文，即使浏览器偏好英文也不自动切为英文                                                                                                                    |
| L02  | 主动切为英文后刷新、跳转及直接打开子页面                 | 当前浏览器保持英文；切回中文后同样保持                                                                                                                              |
| L03  | 切换语言与服务端首屏                                     | 首屏与客户端一致，不出现明显英文闪屏、语言回跳或水合报错                                                                                                            |
| L04  | 逐页检查主要用户流程和现有管理页面                       | 标题、按钮、菜单、弹窗和说明按覆盖清单翻译，必要专有名词保留                                                                                                        |
| L05  | 触发表单校验、空状态、成功及常见失败提示                 | 提示随语言切换，不只翻译静态菜单                                                                                                                                    |

| L08  | 翻译覆盖报告与基础验证                                   | 记录已覆盖和遗漏页面、语言选择与默认行为的验证结果；没有真实调用就不声称生成链路验收通过                                                                            |
| L09  | 中英文分别发起现有账号邮件，含未选择语言及发起后切换语言 | 主题及正文等文案与发起时语言一致，未选择时默认中文，异步发送不受后续切换或其他请求影响；验证码、链接、有效期及原有认证行为保持；模板渲染/捕获与真实投递证据分别记录 |

## 5. 与其他阶段的关系

1. 第一阶段先完成现有界面的中文支持、英文切换及现有账号邮件翻译，独立评审和验收。
2. 后续推进平台凭证、模型销售价格及成本核算等保留规划；复用组织钱包和兑换卡，界面沿用翻译机制，不安排个人人民币钱包或卡密商业改造。
3. 继续补齐运营管理、私有媒体和公网运行方案，新增页面同步提供中英文文案。

本阶段的规划不依赖真实供应商 Key、实际售价、汇率或正式部署资源已准备完成。现有页面若有旧币种或尚未改造的上游行为，按真实状态展示，不冒充已符合商业二开规则。

## 6. 扩展方式与上游改动边界

- 翻译资源、语言选择/记忆及格式化逻辑优先独立组织，遵循现有目录分层和代码风格。
- 复用实际存在的公开接口，在布局或组装入口增加必要的薄桥接；组件只做必要文案和翻译调用接入，不复制整页或改写业务流程。
- 页面较多时仍需逐页接入，不使用全局 DOM 文本替换等方式逃避真实渲染和状态管理。
- 不改变现有数据结构；确需改动公共布局或组件时，按 [上游兼容约束](extension-policy.md) 说明原因、影响、验证和后续合入冲突点。
- [i18n 开发计划](i18n-development-plan.md) 已列出建议库、拟新增模块和必要上游接入点；这些属于设计，实际路径和公开契约以首批验证结果为准。
