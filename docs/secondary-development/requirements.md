# OpenStory 商业化二开需求清单

更新时间：2026-11-06。本文记录需求与当前规划；已有二开及验证边界见 [二次开发说明](README.md)。本次仅更新文档，取消个人独立人民币余额及新增卡密商业改造，复用现有组织钱包和兑换卡。

用户已总体接受 [首期规则确认单](confirmation.md) 作为当前规划基准，可在方案阶段继续调整。正式部署已更正为公网，允许使用 Cloudflare 的部分能力；不再以“内网部署”或“全部独立自托管”为现行前提。接受需求不自动触发开发。

功能与页面细化见 [首期功能规格](mvp-specification.md)，验证标准见 [验收清单](acceptance.md)。二者区分上游已有能力的复用与二开计划，不把兑换卡和组织钱包列为待新增功能。

当前交付优先级已调整：先做 [中文界面阶段](localization-plan.md)，覆盖现有页面并独立验收；后续再推进商业功能。中文界面不以完成模型销售计价或 Cloudflare 选型为前置条件。

## 1. 产品目标

基于 OpenStory 建设面向多个用户的多租户 AI 创作平台。用户通过网页端登录，在所属组织内使用现有钱包、兑换卡及创作功能；平台统一接入外部模型服务，通过用户收费与供应商成本之间的差额盈利。

兑换额度、实际收款、用户消费、供应商成本和其他运营费用分别理解；调用差价不直接等于净利润。本次不新增售卡或发卡管理产品。

## 3. 首期业务边界

- 沿用上游组织成员协作、切换、共享及角色权限，余额和消费归属组织；不新增个人独立人民币钱包。
- 兑换卡及到账余额的兑换次数、有效期和管理方式沿用现有实现，撤销原单次卡、自定义人民币档位、默认不过期及作废等新增商业要求。退款等其他结算规划仍见规则确认单，不在本次实施。
- 经营核算仍需分清实收、兑换额、消费额、原币种成本、人民币成本和调用差价；本次不再规划售卡实收登记后台，成本区分预估与已核实。
- 系统管理员管理用户启停、渠道凭证、模型、价格、钱包及成本，兑换卡管理复用现有入口；调账记录原因。普通用户看不到供应商凭证或成本，管理员默认不开放浏览用户作品的入口。
- 用户素材和作品默认私有，主动发布或分享后开放对应内容，支持撤销后续访问；页面、接口与媒体文件均纳入权限边界。
- 首期不自动清理作品，用户可删除自己的作品，存储和用量限制可配置；作品删除不删除账务凭证。
- 用户输入、生成内容、模型提示词和必要专有名称保持原文；语言切换不改变币种。
- 具体业务政策和结算说明以 [首期规则确认单](confirmation.md) 为当前详细基准。

## 4. 消费结算基准

1. 展示适用售价的预估费与本次消费上限，用户点击生成后在所属组织钱包内预占余额；人民币售价与现有钱包币种的衔接需另行设计。
2. 按已锁定的单价及实际用量结算，不因后续调价或汇率变化追改已完成消费。
3. 成功的可计费子任务分别收费；明确失败的部分不收费，未消费预占释放。后续视频失败不自动退还之前已成功分析、图片等子任务费用。
4. 供应商对失败调用仍收费时记录为平台成本；同一个可计费交付不因技术重试重复向用户扣费。
5. 取消前尚未发出的调用不收费；已提交任务需核对结果。超时、断线或结果不明时先核对，不直接当作失败重发。
6. 禁止透支和超授权上限自动扣款，预占不足以覆盖后续步骤时停止新的付费调用。

上述是其余商业结算规划；销售计价与组织钱包的衔接、精度、舍入、幂等、并发和异常恢复仍需技术设计。本次不要求迁移钱包或历史账务，上游微美元不能直接重新解释为人民币。

## 8. 已确认的工程约束

- 保持项目代码风格，优先采用独立模块、扩展目录、薄桥接层和现有公开接口。
- 尽量不修改上游核心流程及既有数据结构，不做与当前需求无关的大范围重构。
- 确有必要时采用最小范围的侵入式修改，记录原因、影响、验证及上游升级冲突点；不把“低侵入”误写为绝对零修改。
- 中文阶段同样遵守上述要求，翻译资源及语言逻辑独立组织，页面只接入必要能力；完整规则见 [扩展与上游兼容约束](extension-policy.md)。
