## 1. 产品目标

基于 OpenStory 建设面向多个用户的多租户 AI 创作平台。用户通过网页端登录、用卡密充值人民币余额并使用创作功能；平台统一接入外部模型服务，通过用户收费与供应商成本之间的差额盈利。

卡密面额、售卡实收、用户消费、供应商成本和其他运营费用分别理解；调用差价不直接等于净利润。

## 3. 首期业务边界

- 每个用户独立充值和消费，暂不开放成员协作、共享余额、多团队切换、余额转账或提现。
- 卡密及到账充值余额默认不过期；首期不提供自动退款，异常扣费通过管理员追加退回余额记录处理，实际付款退款由运营方线下处理并留痕。
- 售卡可在站外进行，后台可登记实收。实收、兑换额、消费额、原币种成本、人民币成本和调用差价分别展示，成本区分预估与已核实。
- 系统管理员管理用户启停、渠道凭证、模型、价格、卡密、钱包及成本；调账记录原因。普通用户看不到供应商凭证或成本，管理员默认不开放浏览用户作品的入口。
- 用户素材和作品默认私有，主动发布或分享后开放对应内容，支持撤销后续访问；页面、接口与媒体文件均纳入权限边界。
- 首期不自动清理作品，用户可删除自己的作品，存储和用量限制可配置；作品删除不删除账务凭证。
- 用户输入、生成内容、模型提示词和必要专有名称保持原文；语言切换不改变币种。
- 具体业务政策和结算说明以 [首期规则确认单](confirmation.md) 为当前详细基准。

## 4. 消费结算基准

1. 展示人民币预估费与本次消费上限，用户点击生成后按该上限预占余额。
2. 按已锁定的单价及实际用量结算，不因后续调价或汇率变化追改已完成消费。
3. 成功的可计费子任务分别收费；明确失败的部分不收费，未消费预占释放。后续视频失败不自动退还之前已成功分析、图片等子任务费用。
4. 供应商对失败调用仍收费时记录为平台成本；同一个可计费交付不因技术重试重复向用户扣费。
5. 取消前尚未发出的调用不收费；已提交任务需核对结果。超时、断线或结果不明时先核对，不直接当作失败重发。
6. 禁止透支和超授权上限自动扣款，预占不足以覆盖后续步骤时停止新的付费调用。

上述是业务规则；金额类型、精度、舍入、幂等、并发和异常恢复仍需技术设计。上游微美元不能直接重新解释为人民币；真实历史余额若需迁移，先确定转换与追溯规则，不自动删除或转换。

## 8. 已确认的工程约束

- 保持项目代码风格，优先采用独立模块、扩展目录、薄桥接层和现有公开接口。
- 尽量不修改上游核心流程及既有数据结构，不做与当前需求无关的大范围重构。
- 确有必要时采用最小范围的侵入式修改，记录原因、影响、验证及上游升级冲突点；不把“低侵入”误写为绝对零修改。
- 中文阶段同样遵守上述要求，翻译资源及语言逻辑独立组织，页面只接入必要能力；完整规则见 [扩展与上游兼容约束](extension-policy.md)。
