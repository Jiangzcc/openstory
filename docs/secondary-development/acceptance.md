# 首期验收清单

日期：2026-11-03。状态：全部待执行。

本文件是 [首期功能规格](mvp-specification.md) 对应的验收要求，不是新增测试代码、实际执行报告或已经通过的结果。上游既有单元测试不能替代本项目的商业化验收。

第一阶段已优先安排中文界面，独立验收见 [中文阶段计划](localization-plan.md)。本清单描述完整商业首期目标：中文阶段保留现有金额的真实币种，不因翻译就将上游美元展示为人民币；完整人民币账务验收在后续币种改造后执行。

## 1. 账号、权限与模型上架

| 编号 | 场景                                                  | 预期结果                                                       |
| ---- | ----------------------------------------------------- | -------------------------------------------------------------- |
| A01  | 新账号邮箱验证码注册                                  | 创建或关联唯一适用个人空间，余额不自动赠送，不出现共享钱包入口 |
| A02  | 未登录者尝试付费生成，包括直接调用适用服务端入口      | 不产生对应供应商付费任务，要求登录；不能仅网页按钮受限         |
| A03  | 用户修改资源、任务、钱包或空间身份来访问他人数据      | 服务端拒绝，不能从响应泄漏他人作品、账本或凭证                 |
| A04  | 普通用户直接访问运营管理或写入管理操作                | 不可执行发码、调价、配置平台凭证及人工调账                     |
| A05  | 管理员身份访问他人作品                                | 不因平台管理权限自动获得产品中的跨用户作品浏览权               |
| A06  | 用户从页面、接口、已有授权连接或其他适用入口尝试 BYOK | 无法接受或使用用户供应商凭证，不能进入免扣费调用               |
| A07  | 模型未上架、缺少平台配置或缺少明确销售价格            | 不发起新的用户付费调用，提供可理解的不可用原因                 |
| A08  | 用户访问模型页、报价、错误或网络响应                  | 只看到允许展示的销售信息；供应商凭证与运营成本不泄漏           |

## 2. 卡密与人民币账务

| 编号 | 场景                                     | 预期结果                                                             |
| ---- | ---------------------------------------- | -------------------------------------------------------------------- |
| A09  | 有效卡密兑换                             | 按面额精确入账当前用户人民币钱包；不另扣 7% 充值服务费               |
| A10  | 同一用户重复提交或请求响应丢失后重试     | 一次有效兑换对应一笔入账，能核对原结果，不多送余额                   |
| A11  | 两个用户并发兑换同一卡密                 | 全平台仅一次成功，不因不同个人空间而重复入账                         |
| A12  | 核销与入账之间注入故障                   | 不留下不可恢复的已核销未到账或重复入账；最终结果可核对               |
| A13  | 无效或作废卡密；已兑卡再次提交           | 不增加余额，给出合适错误；不会自动撤销其他人的合法入账               |
| A14  | 新发卡密与兑换所得余额                   | 默认不过期，不继承上游充值批次到期扣减政策                           |
| A15  | 运营方批量发码、导出及作废未兑卡         | 权限正确、面额与数量可核对、有操作记录；未兑作废不篡改已兑流水       |
| A16  | 余额、报价、账单、导出或英文界面展示金额 | 用户侧仍为 CNY；细额计算和汇总一致，不仅更换美元符号                 |
| A17  | 需要处理历史美元钱包、卡密或预占         | 未确认迁移规则前不重解释或自动清除；采用方案时可追溯原币种和转换依据 |

## 3. 报价、预占与结算

| 编号 | 场景                                       | 预期结果                                                               |
| ---- | ------------------------------------------ | ---------------------------------------------------------------------- |
| A18  | 多个任务并发使用不足以覆盖全部请求的余额   | 有效预占不超过可用额度，不透支，不把同一额度重复承诺                   |
| A19  | 用户查看预估并提交生成                     | 清楚区分预估、授权上限、预占与最终消费，适用价格可追溯                 |
| A20  | 任务执行中运营方调价或修改成本汇率         | 已授权任务仍按其人民币价格依据结算；新任务采用新价格                   |
| A21  | 技术重试、任务重放、重复结算或重复处理结果 | 同一可计费交付不重复消费；供应商支出与用户收费可分别核对               |
| A22  | 单次模型生成明确失败但供应商收取费用       | 对用户不收失败部分费用，释放对应未消费预占，平台成本单独记录           |
| A23  | 分析和图片已成功，后续视频失败             | 结算成功且符合销售规则的部分，释放未消费部分，不误称全部退款           |
| A24  | 调用发出前取消与提交后取消                 | 前者不发起对应调用；后者按实际任务和交付结果核对，不直接免费或重复发送 |
| A25  | 超时、断线或结果不明                       | 明确显示待核对、保留必要任务身份和账务依据，不擅自重发或宣称退款完成   |
| A26  | 供应商成功，但存储或结果落库故障           | 进入恢复/核对，不把不可用结果冒充已交付，不重复结算                    |
| A27  | 后续步骤将超授权上限或余额不足             | 停止新的付费调用，不自动追加授权外扣款或形成用户负余额                 |
| A28  | 管理员补退、调账或核对异常                 | 有原因、操作者及追加记录，原始消费和调整可以完整追溯                   |
| A29  | 模型下架、账号停用或凭证变更               | 阻止不应发起的新任务，同时不丢弃已提交任务及其结算依据                 |

## 6. 执行与证据要求

- 每项记录环境、执行时间、输入类型、结果和证据位置；未执行或受环境阻碍就标为待验证。
- 并发、故障注入、重放及隔离场景需要相应证据，不能用一次顺序点击或纯函数测试替代。
- 真实模型验收需先明确可用账号与费用授权，记录使用范围和预算；本轮不发起任何调用。
- 演示数据和模拟供应商必须标注；模型 Mock 通过不等于真实供应商链路通过。
- 凭证、原始卡密和隐私素材不进入公开截图或普通日志；证明权限和账务行为不依赖泄漏秘密。
- 实施后按实际变化选择测试，保留上游与二开验证来源，不将现有测试通过数算成本轮新增功能完成数。

目前 A01–A41 全部仅为验收要求，没有宣称新增功能已通过测试或已部署。
