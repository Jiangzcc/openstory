# 管理员图片渠道接入

日期：2026-11-06。开发基线：develop / 71a0ee6ce。

## 原有行为与本轮目标

上游已有内置图片模型、生成/编辑入口、Cloudflare Workflows、R2、组织钱包及生成后的扣费。二开已有管理员文本渠道、平台加密凭证、默认/内部模型槽位和版本化文本快照。本轮复用这些机制，增加管理员图片渠道、动态图片目录、按模型配置参数和 USD 按张规格价卡；不将上游已有能力计作新增。

用户已确认 B 方案、沿用现有美元账务、尽可能开放更多有效参数，以及沿用现有图片流程的扣费节点。文本固定估算、助手预检、组织功能、现有充值/兑换卡和未绑定的内置/native/fal 价格规则保持。本轮没有人民币钱包、汇率换算、支付重构或全面 BYOK 改造。

## 管理与使用

管理员统一入口为“管理后台 → 模型配置”。`/admin/models` 内提供“默认与内部模型”“文本渠道”“图片渠道”三个页签，图片渠道地址为 `/admin/models?tab=image-channels`。页签写入 URL，刷新和浏览器返回可恢复选择；图片渠道没有独立菜单或页面。普通组织角色不能修改平台渠道。公开目录只包含用户需要的能力与价卡，不包含渠道地址、上游绑定、凭证或供应商成本。

1. 保存渠道 Base URL（包括 /v1，不包括 /images/generations）和平台 Key。Key 加密保存，读取只返回提示及引用；更改地址需要新 Key，轮换创建新的不可变 ULID 引用。
2. 同步候选目录仅发起目录读取，不触发付费推理。候选以禁用草稿建立，需要管理员配置准确绑定、能力、参数及价格。
3. 在“绑定内置模型”和“新增自定义模型”中选择。绑定内置模型沿用原有逻辑 ID、名称及作品引用，例如 gpt_image_2；生成与编辑分别填写供应商实际 ID，例如 gpt-image-2。启用绑定后同一个模型走图片渠道，目录不重复新增一项；停用模型绑定或渠道后，新任务恢复原有内置路由。自定义模型仍以 custom-image: 前缀建立稳定身份，已有自定义身份的上游 ID 不可原地替换。
4. 参数按操作配置类型、默认值、枚举或数值范围及验证状态；可配置尺寸、数量、质量、输出格式/压缩、背景、参考与蒙版能力以及供应商实际支持的安全标量扩展。已验证组合可用于创作，待验证及已发现失效的字段保留管理信息。接受字段或返回 HTTP 200 不代表参数生效。
5. 配置 USD 每张价卡，按操作及实际影响收费的参数匹配；更具体的卡优先，同等具体度歧义、缺价及不满足钱包精度的价格在调用前拒绝。供应商成本及币种单独记录，公开报价不冒充实际账单或已知利润。
6. `/images` 沿用原有画面比例、分辨率和数量控件，不展示协议尺寸或高级参数；其余字段使用管理员默认值。数量表示最终目标张数，保留 1/2/4 张。优先每次原生 n=1，按独立素材任务批量；仅在模型不支持单张时选择能整除目标总数的已验证 n，无法精确表达的数量不可选择。单输出入口仍固定请求单张。

## 用户端规格与管理员默认值

用户选择画面比例和分辨率后，共享的规格解析器按当前文生图/图生图操作的已验证 `size` 枚举推导实际请求尺寸；服务端报价使用同一解析器并冻结结果。优先精确匹配，供应商合法尺寸按现有短边分辨率档位选择；只有一种输出规格时沿用原有固定尺寸提示。只有自动尺寸的模型显示由模型决定，不伪造比例或分辨率能力；超过当前解码预算的规格不进入可选列表。

`quality`、`output_format`、压缩率、背景及安全标量扩展保留在管理后台配置，不在创作页增加高级设置。报价和提交都使用当前管理员默认值，复用旧作品不会恢复旧的隐藏参数或原始 `size` 来覆盖当前基本控件。旧作品中的外层请求数与原生 n 换算成最终目标张数；不能用现有数量选项精确表达时明确提示，避免静默多生成和多扣费。

## 执行、快照与存储

触发端冻结准确上游绑定、能力、参数、价卡和凭证引用，父子任务沿用同一份版本化图片路由；执行过程中只解析不可变凭证引用，不重读可变模型选择或价格。启用的内置绑定优先于该图片模型原有 fal/native 路由，组织上无关的供应商 Key 不改变此绑定。启用但缺少可用操作或价卡时明确拒绝，不回退；停用内置绑定恢复原有内置路由，停用自定义模型则保留历史身份且拒绝新任务。旧任务始终沿用启动时的绑定和价卡。读取已保存默认配置时，暂不可用的内置/自定义图片 ID 仍保留，避免拖垮全局配置及管理页；新保存默认模型和执行仍分别进行可用性校验。

Workflow 图片快照使用 v2 字典格式，对渠道、参数集和价卡集去重，兼容 v1 及早期数组快照。图片路由的 UTF-8 预算为 256 KiB，在渠道/模型保存前检查，并在触发编码时兜底；禁用项不占执行快照预算。共享参数和价卡可复用字典，不因整个原始注册表超过 1 MiB 就直接失败；不同配置确实超限时保存会给出可翻译错误，仍可停用渠道来恢复。

兼容适配器使用项目已有版本的官方 OpenAI SDK，通过 JSON /images/generations 和 multipart /images/edits 调用。单参考使用 image，多参考保持有序 image[]，mask 只有在已配置验证通过时可用。关闭 SDK 重试和日志，不自动切换供应商。参考素材从授权的组织存储读取或有预算地下载，内部相对地址不会作为供应商可下载地址。

实际图片字节用于检查 MIME、宽高和资源大小，并在返回可交付结果前用 Photon 做真实像素解码。仅文件头、CRC 正常但像素流损坏的图片会明确失败。解码前检查编码字节、尺寸、像素及解码缓冲预算，解码对象立即释放；预算是接纳上限，不能视为生产内存压测结论。固定规格不符明确失败；自动尺寸保存实际结果，不裁剪、拉伸后冒充上游参数有效。数量不足只交付和计量有效结果；超量不会增加已授权扣费。

生成和全部输出的 R2 存储在同一个 step 内完成，只有小型元数据穿过 Workflow 检查点。任务调用记录使用组织隔离的 app_metadata 命名空间，包含稳定尝试标识、输入摘要、submitted/stored/unknown 状态与小型存储结果，不存明文 Key 或图片字节。已存结果先恢复再检查新余额；新增尝试在余额校验成功后才写入 submitted。生成步不自动重试，单独的记录步可重试保存小型结果，D1 写入失败不会再次调用供应商。已提交但结果未知时不自动再次推理。账务幂等不冒充供应商恰好执行一次。

新增图片渠道始终使用平台凭证；组织上无关的 fal/OpenRouter Key 不免除平台消费预检。生成并存 R2 后按快照价卡和实际有效张数进入现有幂等扣费，再保存版本和尝试选中；未选中的变体沿用现有收费语义。未使用预占沿用所属任务收尾清理，已扣交易不因选中失败自动撤销。

## Qwen 比例与分辨率实测（2026-11-06）

通过原有管理员表单和服务端版本校验，将用户本地开发配置从 revision 4 保存到 5：文生图补充三个 720p 尺寸和 1152×2048，图生图按单参考的成功尺寸补充三个 720p 尺寸；既有尺寸保留。渠道及凭证引用、两张售价卡、操作绑定、参考数上限和所有参数默认值逐项比对保持相同。这里的新增编辑尺寸依据单参考 JPEG 证据，并不表示“任意尺寸 × 格式 × 参考数”的组合均已验收；最大双参考和既有 PNG 能力保留，其新增大尺寸组合仍待验证，不能描述为已通过。

另通过应用真实 `generateCompatibleImages` 适配器进行 1 次验证（独立于上表 21 次）：读取 revision 5 的当前后台默认值，使用一张合成参考图，16:9 + 720p 推导为 `size=1280x720`，实际发送 `n=1`、`response_format=b64_json`、`output_format=png`。约 113 秒后 HTTP 200，返回 1 张 1280×720 PNG（446,081 字节），完整像素解码通过，`mismatches=[]`。该调用证明单参考横图在应用默认 PNG 下可用；双参考 PNG 及其他尺寸/格式组合仍分别按其自身证据评价。验证只读应用配置，没有触发应用素材工作流或其钱包扣费。

## 最小桥接与升级关注点

新增职责位于 models/stills/billing/studio 各自领域，使用现有 API/server fn、scoped-db、主库与 CAS，不新增平台权限豁免。图片身份、静态 schema/选择器、配置快照、费用来源及生成分支是必要的上游桥接点；内置请求构造器保持窄类型。图片使用独立 ImageVia 扩展，视频 MediaVia 及轮询路由保持原边界。generated_assets 的 provider 仅扩展 TypeScript 类型，不改变 SQL 定义。

本轮沿用既有 app_metadata，无 schema 变更或手写迁移。原有超长核心文件仅做必要桥接，不顺便重构。上游更新时重点复核上述 schema/目录、快照及生成存储的调用契约。

## 真实渠道响应兼容修复（2026-11-06）

用户报告的 Studio 素材 01M6RJ6PB42HMA1YPJK3G41YEP 在响应归一化时失败。根因是网关返回 HTTP 200 和有效 PNG 的 b64_json，同时把未使用的 url 写为 null；原 schema 仅接受字符串或字段缺省，因而将整份成功响应误判为 invalid_response。JSON/schema 处理错误还丢失已收到的 HTTP 状态，日志因此显示 HTTP undefined。

适配器统一将可选响应字段的 null 归一为未提供，覆盖 b64_json/url、可选规格和 usage 及 token 明细。图片有效载荷仍必需，非空的错误类型、损坏像素流、资源超限及固定规格不符仍会拒绝；没有按渠道名或模型名做特判。HTTP 状态在收到响应头后立即保存，后续解析和检查失败保留该状态，下载失败保留下载自己的状态；尚未收到响应时不虚构状态。错误继续清洗，日志不包含供应商原始响应、Key、headers 或 cause。

修复前通过同一已存渠道、模型 longshine/Qwen-Image、原提示词及 1024x1024/n=1/PNG 参数真实调用，确认返回 data[0].url=null、有效 b64_json，HTTP 200，解码后为 1024×1024 PNG（1,509,103 字节）。修复后再次直接执行项目生产适配器 generateCompatibleImages：只发送一次真实请求，63,442 ms 返回 complete，requestedCount/actualCount/returnedCount 均为 1，mismatches 为空，真实像素解码通过。两次诊断共发起两次供应商推理，SDK 自动重试为零；诊断只读取本地路由和加密凭证，没有写应用素材或组织钱包。临时显式启用的真实测试文件已删除，常规回归仍使用合成/Mock 数据。该证据覆盖真实供应商和生产适配器，不冒充完整网页 → Workflow → R2 → 扣费的真实渠道验收。

只读核查原失败素材：status=failed、outputs 为空、costMicros 为空，未找到该 workflow/素材的消费交易；尝试记录为 unknown，且没有可恢复的已存输出。修复不改写旧任务，也不自动重新提交；后续生成使用新任务。

## 图片请求截止时间修复（2026-11-07）

用户提供的 `request_aborted` 日志对应 2026-11-06 15:54:38 UTC 开始的参考图生成。只读本地 Explorer 运行记录证实，道具、地点、角色生成步骤分别在 180,063、180,157、180,162 毫秒后失败；步骤本身允许五分钟，先触发的是适配器原来的 180 秒总截止时间。截止信号传给 SDK 后被包装成调用方中断，因此此前日志误记为主动取消；同秒失败来自同时开始的请求，并非 `channel prune` 导致。

本轮二开将兼容图片请求的总预算提高到十分钟，覆盖等待响应、读取 JSON 和下载输出图片；Studio 与共用参考图/静帧的生成并存储步骤统一使用十五分钟预算。按最终生效的中断信号区分 `request_timeout` 与 `request_aborted`，保留已观察到的 HTTP 状态；未收到响应时日志写 `no_response`，并补充安全的运行耗时和截止预算。默认尺寸、模型绑定、密钥、价卡与生成后的扣费节点不变。

SDK 和付费生成步仍不自动重试，已提交但没有收到结果的尝试保持 `unknown`；延长等待不代表可以重复提交同一尝试。历史失败实例不会因代码更新自动变为成功，也未清除已有尝试记录或重发这些用户任务。

新增合成传输回归覆盖四分钟后成功、响应头之前截止、HTTP 200 后 JSON 读取截止、图片下载截止和显式调用方取消。修复前五项中四项失败，证明原截止/分类问题；本轮验证没有再次调用供应商或写入业务钱包。最终整合回归为 13 个文件、227 项测试通过；全仓类型检查、lint、dead-code 和生产构建通过，lint 与 knip 保留原有警告/配置提示。已有本地 Vite/Workerd 服务的 GET /docs 返回 200；真实供应商在新十分钟预算下的用户任务尚待重新发起验收。
