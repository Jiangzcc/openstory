# 首期业务规则确认单

首次确认：2026-11-03；更新：2026-11-06。状态：按最新决定修订的首期规划基准，已有能力复用与未实施商业规划分别记录。

用户于 2026-11-03 总体接受原建议，后续明确保留上游组织能力；2026-11-06 取消“每用户独立人民币余额”及新增卡密商业改造，沿用现有组织钱包和项目自带兑换卡。本文据此修订相关条目，其他商业规划保持原有范围。接受规划基准不表示功能已经实现，也不自动要求开始开发。

## 1. 已确认，不重复询问

- 基于 OpenStory 二开，develop 承载本项目改动，明确区分上游与二开。
- 首期为网页端创作消费，不新增第三方直接调用模型的通用 API 产品，保留上游已有创作 API/MCP。
- 复用项目自带兑换卡及组织钱包，不再新增卡密商业方案或每用户独立人民币余额；现有金额按实际币种解释，不新增在线支付渠道。
- 平台接入包括 fal/OpenRouter 在内的外部模型，允许访问外部 AI，赚取收费与供应商成本的差额。
- 不允许用户自带供应商密钥；平台运营方统一配置和管理凭证。
- 界面默认简体中文，支持切换英文。
- 正式平台面向公网访问，允许使用 Cloudflare 的部分能力；内网部署不再作为现行需求。

## 2. 当前首期规划基准

D01、D07 改为复用上游组织钱包和兑换卡；D08–D10、D14 撤下由个人钱包及商业发卡方案派生的要求，D04–D06 的售价与结算规划须另行设计和现有钱包的衔接。D13 继续采用公网部署并允许使用 Cloudflare 部分能力。已有组织和兑换卡能力不计为二开新增，其余未实施规划仍需配置与技术设计。

| 编号 | 业务事项                   | 当前首期规划基准                                                                                                                                                                                                                   |
| ---- | -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D01  | 租户及钱包归属             | 沿用上游 Organization、组织钱包、成员邀请、切换、共享及角色权限。取消每用户独立人民币余额，不因旧个人钱包规划限制组织协作                                                                                                          |
| D02  | 注册、登录与试用           | 复用邮箱验证码登录，允许自主注册；付费生成要求登录，注册不自动赠送余额。其他登录方式及营销赠送后续再扩展                                                                                                                           |
| D03  | 开放的模型和创作能力       | 首批商业接入围绕 fal/OpenRouter；由运营方维护可用模型白名单，已配置平台凭证、价格及可用性验证后上架。复用其支持的上游创作流程，依赖其他渠道的功能随接入范围开放                                                                    |
| D04  | 用户售价及调价             | 按渠道、模型及规格配置人民币销售单价，再按实际用量计费；允许用成本换算和加价倍率辅助生成售价。生成时锁定单价及报价上限，调价只影响新任务；首期不另收充值服务费，不做订阅套餐                                                       |
| D05  | 外币成本换算               | 由运营方维护有版本的结算汇率，保留原币种成本及适用汇率。成本核算与用户账单分开，汇率或供应商账单后续变动不追改已完成的用户收费                                                                                                     |
| D06  | 余额、失败与取消的结算     | 先展示预估费用和本次消费上限，点击生成即授权并在所属组织钱包预占；不允许透支或超上限自动扣费。成功的可计费子任务分别结算，明确失败的部分不收费，未消费预占释放；状态未知的任务待核对。人民币售价与现有钱包的衔接待设计             |
| D07  | 现有兑换卡复用             | 使用项目自带兑换卡（Gift Code/礼品码），按现有规则兑入所属组织钱包。撤销新增商业卡密、自定义人民币面额档位、全平台单次兑换、批次/导出/作废等二开要求；现有能力保留                                                                 |
| D08  | 有效期及退款               | 兑换卡及到账余额有效期沿用现有实现，不新增默认永不过期政策。首期不新增余额转账、提现或自动退款；异常扣费的追加调账及线下退款留痕仍为其他结算规划，不在本次实施                                                                     |
| D09  | 运营后台及权限             | 系统管理员管理用户启停、平台渠道凭证、模型和价格、钱包流水与成本核对；兑换卡复用现有管理入口。人工调账需原因与审计记录。普通用户看不到供应商密钥和成本；管理员默认不开放浏览用户作品的能力                                         |
| D10  | 经营报表                   | 分别理解实际收款、兑换额、用户消费、供应商成本和调用差价；预估与已核实成本分开，兑换额不直接算作实收或净利润。不再新增售卡实收登记及发卡运营后台                                                                                   |
| D11  | 素材隐私及分享             | 用户素材和作品默认私有；用户主动发布或生成分享链接才开放相应内容，允许撤销后续访问。界面、接口和媒体文件都按权限控制，供应商读取素材按必要范围授权                                                                                 |
| D12  | 语言记忆及翻译范围         | 用户端、运营后台、常见提示及现有账号相关邮件支持中英；首次默认中文，语言选择先在当前浏览器保留，不做跨设备同步。账号邮件随发起操作时的界面语言发送，未选择时默认中文。用户原文、生成内容、模型提示词和必要专有名称保持原文         |
| D13  | 公网部署及 Cloudflare 使用 | 正式平台面向公网访问，允许使用 Cloudflare 的部分能力及访问外部 AI。按现有上游依赖、成本、运维和部署条件评估托管与自建的分工；不要求完全自托管，也不直接认定全部服务上 Cloudflare。主应用、任务、数据、媒体与导出均需按选定方案验证 |
| D14  | 数据、存储及存量账务       | 首期不自动清理用户作品，用户可按权限删除作品，存储及用量限制可配置；作品删除不删除账务凭证。沿用现有钱包币种及账本，不安排人民币钱包迁移，不把美元存量重新标成人民币                                                               |

D01、D07 已按 2026-11-06 的决定修订：组织协作与共享钱包、兑换卡均沿用现有能力，不再将个人钱包或商业卡密列为待开发任务。此调整不取消多租户权限隔离，也不表示现有兑换功能已经完成生产验收。

D03 是接入范围建议，不意味着现有 fal/OpenRouter 支持的模型都已经完成本项目的验证，也不承诺只填一个 URL 就能接入任何供应商。

D04 建议由运营方持续维护模型售价，具体每个模型的价格和加价倍率属于运营配置；没有设定任何默认实际汇率或利润率。模型缺少明确售价时不向用户开放付费调用。人民币模型售价与现有微美元组织钱包的衔接尚待设计，保留这项规划不等于要求转换兑换卡面额、钱包或历史账务。

## 3. 结算建议的具体含义

以下是 D06 的展开，按当前首期规划基准执行，尚未实现：

- 按用户看到并同意的价格及币种规则结算，后台成本变化不成为任意追加扣款的理由；报价、预占及扣费必须明确和现有组织钱包的对应关系。
- 一次视频流程可能包括分析、分镜、图片和视频等可计费步骤。前面成功且符合收费规则的步骤可以收费，后续失败只释放对应未消费部分，不自动退款整条流程。
- 某次生成明确失败，建议不向用户收取这次失败生成的费用；供应商仍收费时记录为平台成本。技术重试不能让同一个可计费交付重复计费。
- 取消发生在调用发出前的部分不收费；已提交供应商的任务需要核对结果，按是否成功提供对应结果结算，不能仅凭点击取消就当作没有产生消费。
- 超时、断线或状态不明时先展示待核对，不在结果不明时承诺退款，也不因重发造成重复供应商支出。
- 对预占不能覆盖的后续步骤，停止发起新的付费调用，不以透支完成整条任务。已产生但超出用户授权上限的供应商支出不自动转嫁给用户。

## 4. 还需要用户提供的事实信息

这些是环境或业务现状，不能由方案推测：

- 已有的 Cloudflare 账号/服务、自有服务器或其他云资源，以及部署预算和目标访问区域；如有服务器，补充操作系统、CPU、内存和存储。尚未准备时可标为未定，不预设必须购买服务器。
- 预计初期同时在线人数及同时生成任务数量，供容量和限额设计使用。
- 是否已经有真实用户、已发放或售出的兑换卡，以及需要保留的存量余额和账务；不因本次规划调整迁移或转换这些数据。
- 是否已有可使用的发信渠道和供应商账号；只需确认是否具备，不在聊天中提供密钥。

具体模型售价、结算汇率、正式管理员、域名和产品名称等作为上线配置登记；模型上架前必须具有可用凭证与完整价格规则。上述配置按 D03–D05 和 D09 的当前规划基准维护，具体值仍未设置。

## 5. 由技术设计负责的事项

以下事项不需要用户逐项选择实现方式，也不冒充已经实现：

- 翻译资源、销售计价与现有钱包的衔接、金额精度及服务分层；不据旧规划新增人民币钱包或迁移账本。
- 现有兑换卡仅按实际影响做复用回归，历史风险与未验证项如实记录，不将其自动转为卡密商业改造任务。
- 凭证保护、权限校验、密钥相关入口限制及完整调用链审计。
- 任务持久化、故障恢复、预占释放、可解释账单和必要监控。
- 在确定的部署环境下设计限流、并发、上传和存储参数，并通过验证确定合理默认值。
- 建立多租户、计费、中英切换及选定公网部署方案的验收清单，现有兑换卡按复用范围记录回归场景。

这些技术设计必须服务于已确认的业务规则，不能借技术实现替用户决定收费、共享钱包、退款或素材公开策略。

- 2026-11-03：用户总体接受推荐方案作为当前首期规划基准；保留在方案阶段继续调整的空间。
- 2026-11-03：允许使用 Cloudflare 的部分能力，D13 不再要求全栈独立自托管。
- 2026-11-03：用户明确“不是内网，是公网”，已更正 D13；此前内网讨论仅保留为历史，不构成当前部署限制。
- 部署资源、初期规模、真实存量账务和发信/供应商账号等事实仍待补充；具体 Cloudflare 服务与自建边界尚未选定。
- 2026-11-03：用户将中文界面指定为第一阶段优先项；默认中文及英文切换先覆盖现有页面，商业功能后续推进，详见 [中文阶段计划](localization-plan.md)。
- 2026-11-03：用户明确要求代码风格一致，优先独立模块、扩展目录、薄桥接和公开接口；核心或数据结构的必要侵入需最小化并说明原因、影响及升级冲突点，见 [工程约束](extension-policy.md)。
- 2026-11-03：用户确认“纳入现有账号相关邮件”；第一阶段包括现有登录/账号邮件的中英文主题及正文等文案，语言取发起操作时的界面语言，未选择时默认中文，尚未实施。
- 2026-11-06：用户取消之前规划的“每用户独立人民币余额”，并确认项目自带兑换卡，无需新增卡密商业改造；本次仅更新文档，沿用组织钱包与现有兑换规则，撤销相关定制面额、单次核销、永不过期和售卡后台要求。
- 其余商业规划仍未实施，本次不启动业务代码修改、充值、模型调用或部署。

本轮只整理需求与建议，不启动代码修改、人民币迁移、真实模型调用、收费、部署或提交推送。
