# 首期需求与业务规则确认

首次确认：2026-11-03；更新：2026-11-16。本文合并原需求清单和首期规格，作为业务范围的统一入口；规划被接受不表示已经实现，也不自动启动开发。

## 已确认的目标与工程前提

基于 OpenStory 建设多租户 AI 创作平台，首期用户通过网页登录、使用所属组织钱包充值消费和创作。平台接入包括 fal/OpenRouter 在内的外部模型，通过收费与供应商成本之间的差额盈利；调用差价不直接等于净利润。

- `develop` 承载二开，保留上游组织协作、组织钱包、兑换卡、Stripe 和创作 API/MCP。
- 项目尚未上线，不增加历史数据、任务、协议或配置兼容层；系统管理员仅一个，管理配置不考虑并发。
- 一般沿用上游异常停止后的行为，不默认增加恢复日志、重放、定时补投或统一恢复机制。
- 首期不新增第三方直调模型的通用 API 产品、在线支付渠道、订阅套餐、提现或商业发卡后台。
- 默认简体中文，支持英文；正式面向公网，允许使用部分 Cloudflare 能力和外部 AI。
- 不允许用户自带供应商密钥是业务目标；平台统一凭证及相关调用链改造仍未全部实施。

## 结算规划的具体边界

以下为 D04–D06 的业务要求，尚待销售计价与现有组织钱包衔接设计：

- 模型没有明确销售价格时不开放对应商业付费调用；不得将上游微美元直接当作人民币或只改货币符号。
- 一次流程的分析、图片、视频等成功交付可分别收费；后续失败只释放相应未消费部分，不自动全额退款。
- 明确失败而供应商仍收费的部分记平台成本，不重复向用户收取同一可计费交付；供应商原币种成本与销售金额分别留存。
- 发送前取消的部分不调用；发送后按实际交付核对，不因点击取消就认定没有消费。
- 超时、断线或未知结果先核对，不擅自重发、承诺已退款或将授权上限以外的支出自动转嫁给用户。
- 预占不足时停止新的付费步骤；调账追加组织归属、原因、操作者和对应消费依据。

这些规则不要求新增通用重启恢复协议。持久化、重试和核对沿用实际选定机制，技术方案不得替用户另定收费、退款或共享规则。

- 现有 Cloudflare/服务器资源、预算、目标访问区域、初期在线与生成规模，以及可用发信渠道和供应商账号。

- 默认私有媒体与分享权限、具体 Cloudflare/自建边界及上线验收。
