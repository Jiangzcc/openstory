## 必要的兼容修复

**MCP 身份分类。** 上游将所有非 OAuth 的 `getSession` 结果标为 `api_key`。本轮用真实 Better Auth 内存 adapter 签发 Cookie，复现没有 API Key 的管理员也可获得新增跨组织能力。现区分 `session` 与 `api_key`，Cookie 保留活动组织；已验证的 API Key 管理员仍可使用上游跨组织功能。没有恢复已取消的“管理员默认不浏览用户作品”规划。`auth-cookie.test.ts` 进一步真实签发 Key，覆盖 Bearer、`x-api-key`、不同用户 Cookie 混用及无效 Key 拒绝；组织归属查询和合规检查为明确 Mock。

**即时估价。** handler 采用页面选择的模型及分辨率后，`prepareContinueEstimate` 还必须将图片模型、视频模型和分辨率传入 `computePlan.sequenceOverrides`。否则 D1 尚保存 720p 时，页面请求 1080p 仍会按旧档计价。真实内存 D1、规划和配置价卡回归先失败，再通过；示例报价从错误的 100000 修正为 900000 微美元。模拟保存失败后，重新从真实 D1 读取会恢复旧档报价，余额不变，没有供应商请求。这里仍使用现有美元组织钱包，没有实施人民币销售规则。

**界面缓存。** 上游场景列表的 `React.memo` 比较遗漏 `resolution` 与 `onResolutionChange`，单独更新规格可被跳过。本轮补齐两项，单独提交为 `f92501937`。直接抽取当前真实 comparator 执行的相同诊断，在节点 14 提交上两项均失败，修后两项通过；没有为测试新增生产导出或复制比较器。

**依赖边界。** 保留 `i18next 26.7.1`、`react-i18next 17.1.11`、`openai 7.32.0`。Better Auth 主包、插件、core/oauth-provider override 与生成 CLI 均固定为 `1.7.16`。价卡 schema 使用上游新 `/schema` 导出，evaluator 仍走原入口。Tiptap 的上游 core/pm override 继续保留，不借本轮扩展升级范围。

**运行时配置。** `compatibility_date` 仍是 `2026-10-08`，保留 `enable_request_signal`、本地 D1 占位绑定和 `upload_source_maps: false`。Vite 与 root Wrangler 分别使用其锁定的 workerd 版本，更新 AGENTS 中原先只适用于旧版本的说明。

**编辑回放。** 对白用例原先为检查一个镜头的台词，先读取场景、所有镜头和失效状态，再逐镜头取对白；失败轮次的前三步已耗时约 17 秒。现直接调用同一个 `list_shot_dialogue`，仍按所选版本精确比较目标台词，20 秒预算和其他全序列失效断言不变。

另一次对白补跑在保存请求仍在途时就耗尽了上述 20 秒，随后清理删除序列；原保存到发出后 35.5 秒才进入 handler，此时已返回业务 NotFound。该错误出现在清理开始后约 14 秒，不能当成初始内容保存失败。现对 UI 保存和删除台词均监听本次点击新发出的 POST，等待该请求的完整响应后再开始原持久化断言，没有重试点击或保存。HTTP 200 只作为传输检查，序列化的业务错误仍由后续真实 MCP 内容断言揭示。

新增显式 `E2E_REPLAY_TIMEOUT_MULTIPLIER`，只用于这三个编辑文件的十三处回放预算；未配置时不放大传入预算，仓库 CI 未新增倍率配置，录制模式不应用该倍率，非法倍率明确报错。本机后续回放显式设为 3；内容断言及上游跳过规则保持不变。独立进程验证默认、倍率、非法输入和录制共 12 条路径通过，局部格式及类型感知 lint 检查通过。开关改为单次提交后新增的状态等待预算见下文，不将其描述为逐条保留旧重试超时。
