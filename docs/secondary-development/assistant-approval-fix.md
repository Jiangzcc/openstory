# 助手工具确认恢复修复

日期：2026-11-07。基线：本地 `develop` 的 `3b203b3b6`。状态：二开修复已实现并完成下述本地验证；提交状态以 Git 记录为准，未推送或部署。

## 原有行为与原因

工具确认、服务端执行、持久化和组织权限来自上游助手。原界面只在 `interrupts` 中查找 `kind: 'tool-approval'`，但浏览器仅注册 `replace_unsaved_text`，没有注册服务端删除角色等工具。当前 SDK 会将这些审批提供为可恢复的 `generic` 中断，并在 metadata 中保留原始工具审批绑定。点击允许或拒绝时，原筛选都找不到对象，通过可选链静默结束，没有发出恢复请求。

本次是兼容修复，不把上游已有的工具审批、角色删除或会话持久化计为新增能力。

## 改动范围

- 新增 `src/assistant/ui/assistant-approvals.ts`，复用 SDK 公开的 `@tanstack/ai/client` 浏览器入口读取原始绑定。按工具调用 ID、中断 ID、运行 ID 和恢复版本关联卡片，通用中断提交 `{ approved }`；已注册工具的审批继续使用布尔签名。
- `assistant-conversation.tsx` 只把原来的内联筛选换成上述入口。仅处理可回答的等待或错误状态；WeakSet 防止同一旧快照连续点击重复提交，新错误快照仍可重试。
- 边界测试只放行 SDK 的官方浏览器子入口，继续禁止客户端引用 AI 根入口、adapters 和 testing。
- 演示连接原来使用空 schema 哈希，当前 SDK 无法恢复；改为有效且由真实 SDK 测试核对的固定 Mock 契约。演示页补齐模型配置和目录缓存，避免服务器 stub 令输入框一直等待。

未修改工具定义、删除权限、服务端恢复协议、计费、持久化表或数据库结构。后续合入上游需复核会话组件的审批入口、SDK 客户端子入口及中断绑定契约；演示 descriptor 变化由回归测试提示。

## 验证证据与边界

- 8 个相关测试文件、93 项通过，覆盖助手请求、连接、工具、D1 存储和客户端服务端导入边界。
- 新增 16 项审批回归使用真实 ChatClient、SSE、`chat()`、内存持久化和 Mock 模型：允许执行一次，拒绝不执行，刷新后两种决定均可恢复，多项审批统一恢复，同一旧快照重复点击只提交一次，失败后的新快照可重试。旧 helper 在两项旧快照连点测试中确实失败。
- 演示连接新增 3 项真实 SDK 测试；旧 descriptor 的三项测试均失败，修复后通过。
- 浏览器在独立 Storybook 的模拟删除卡片上实际点击 Allow、Deny，分别进入完成和拒绝状态，确认按钮消失，两种路径均无页面异常。证据位于本机临时目录 `openstory-assistant-approval-20261107`，包括 `browser-results.json`、脚本和点击前后截图。
- 全量 `bun typecheck`、定向 type-aware lint、格式和 diff 检查通过；lint 保留相关上游文件原有警告。

验证没有调用真实供应商或操作用户的实际角色。浏览器覆盖模拟删除卡片，角色工具执行和刷新恢复由真实 SDK 加 Mock 工具的集成回归覆盖；未将它表述为用户会话中的实际删除验收。
