## 原有行为与业务动机

上游页面、静态目录、帮助内容和账号邮件主要使用英文。上游已有的团队、余额、充值、BYOK、模型调用、API/MCP 与创作流程属于复用基础。本轮二开增加默认简体中文、英文切换及独立语言资源，供后续商业功能复用；该阶段没有实施商业计价、卡密改造、禁用 BYOK、多租户规则或公网部署。2026-11-06 已取消个人独立人民币余额及新增卡密商业改造，现有组织钱包和兑换卡继续复用，现行范围见 [规则确认单](confirmation.md)。

## 实际实现

- 使用 i18next 26.7.1 与 react-i18next 17.1.11，锁定精确版本。调用以英文原文为键，例如 t('Welcome')，保持标点、点号和冒号为普通键内容。
- 平台基础位于 src/platform/i18n；React hooks、语言切换组件、业务语言包和应用组合入口统一位于 src/ui/i18n。平台不反向 value-import 业务域。
- 默认 zh-CN，支持 en。openstory_locale Cookie 记住选择。Router 为每个 SSR 请求创建独立实例，传递和水合语言值，避免共享可变实例和跨请求串语言。
- 应用布局、文档和公开播放页提供语言入口；登录页按最新确认不显示切换组件。切换只更新语言与文案，不清空编辑器或创建业务操作。
- 应用资源分为 21 个命名空间，共 4487 条词条（含本次复审补齐项），按命名空间计数并含重复文案；平台另有 auth/common/mail 共 27 条资源。两种语言均独立保存于 JSON。
- 日期、时间、相对时间与数字使用当前语言格式；币种与数值保持上游真实含义，没有将美元替换为人民币。
- 异步通知通过 useLiveTranslation 在完成时读取当前语言。订阅和任务 effect 不因 t 的语言绑定变化而重新执行。
- 模块级显示辅助函数使用可选翻译参数，原有不传参调用仍输出原英文。历史摘要和已存的下载/重试消息在显示层适配，不改记录、协议或表结构；未知文本保留原文。
- 风格分类沿用原始分类键，内置风格支持中英文名称与说明检索，检索结果仍返回原始记录；用户自建风格名称不送入模板翻译。
- 价格页的服务端目录和影片示例使用 src/billing/ui/localize-pricing.ts 显示桥接，仅匹配已知完整模板，保留金额精度、美元符号、数量、模型与供应商名称；未知上游新格式原样回退。FAQ 直接对应上游共享问答原文，并有资源覆盖回归。
