## 原有能力与根因

上游已有流式场景拆分、镜头/锚帧 upsert、脚本版本、对白选择、活动日志和独立分析入口。二开此前已把可信 Storyboard 根身份传到 SceneSplit，并保护部分生命周期状态；内容写入仍直接使用普通方法。根失败后保留实例 ID，或者新根接管后旧子任务继续执行，都能改写场景、镜头、脚本、对白等数据。仅在步骤开始前查询一次、解析子实例名称或发送终止请求，不能约束真正发生写入时的竞争。

## 本批实现

新增组织内的 `scopedDb.storyboardContent(owner)`，复用既有 DB 方法并只暴露本批写入面。每条 INSERT、UPDATE、DELETE 同时核对组织、序列、当前根实例/显式可信 claim 和 `processing` 状态；目标场景、镜头、脚本、对白、素材通过真实父关系约束到该序列。条件 INSERT 同样保护新行和冲突更新，保留 schema 的 ULID、时间、布尔、JSON、显式 NULL 及默认值语义，并采用三行分组限制参数量。

SceneSplit 在执行步骤前绑定这组方法，覆盖流式/最终标题、场景、镜头及锚帧、镜头链接和裁剪、脚本全部 split/fallback 分支及选择指针、对白 claim 降级/旧选择清理/新版本、素材 firstMention 和完成活动。脚本初始版本及选择指针改为同一 D1 batch，失败后不会留下重试跳过的孤立 seed；原对白和 fallback batch 保留提交边界。

方法前后检查也约束已有版本、同值对白和空输入等返回路径，写入安全仍由 SQL 决定。写入报错后重新确认归属：确认失去所有权时保留原 cause，并在步骤回调内部转为 Cloudflare `NonRetryableError`；无法检查时传播具名、可重试的检查错误，双重失败的 cause 保留两个错误；仍拥有序列则保留原写入错误。引擎 abort/reset 原样传播。完成日志不再吞掉失去或无法确认所有权的错误；普通活动写入故障仍按既有 best-effort 处理。

没有显式根身份的独立调用维持原行为。本批不新增 schema、迁移、绑定、cron、依赖、公开 API、计费规则或通用 workflow read hatch。
