# P3 / GC-03：启动占槽与持久恢复

本批承接[生命周期事件归属](../20261114-p3-g03-notification-ownership/README.md)，处理创建请求尚在途时的第二次启动，以及创建回执或确认回写丢失后的恢复。GC-03/P3 仍为 in-progress，P4 未开始。

## 原行为与根因

旧启动器先把 raw claim 写进 sequence 槽，再调用通用 trigger。raw claim 不能解析到实例绑定，后来的请求把它当作 failed；在首个 create 返回前即可接管并另起一轮。任意 create 异常也会写失败，调用方随即释放余额预占，即使实例可能已经被接收。

修复前的两项确定性回归共 23 项，21 通过、2 失败，分别复现上述在途接管和回执丢失误记失败。预占和 Continue 设置的补充回归共 49 项，47 通过、2 失败，复现了待确认任务的预占被清空和设置被恢复。

独立审查另发现占槽已提交、方法回执丢失后预占仍被清空的窗口；新增单项回归先失败，随后将占槽 await 的不确定结果也接入同一 pending 协议。

## 当前协议

1. 请求先完成原有输入/权限与模型配置准备，生成环境范围内的最终实例 ID。
2. scoped DB 在同一 D1 batch 中完成 CAS、processing/清空旧错误、持久启动快照和开始活动。启动快照是占槽的必填参数，包含本次语言、模型/路由、设置和原 reservation ID，不含供应商密钥值。
3. 原始投递和恢复只使用该实例 ID 与同一 prepared 快照。同 ID 已存在时确认原请求，不为失败实例自动生成另一代 ID。通用 trigger 的既有代际策略保持原状。
4. 未确认记录对应的实例暂不存在时保持 pending。请求侧可重投原请求后继续拒绝新一轮；cron 会重新投递当前 owner 的未确认记录，覆盖 D1 提交后请求中断的情况。未知状态不能放开互斥。
5. 确认回写按组织/sequence/实例守卫，不覆盖已经到达的完成/失败结果。占槽方法、创建或确认返回错误时保留 cause 和实例/预占身份，以启动待确认错误向上传递。清理逻辑只保留该待确认任务自己的预占；另一个请求的预占照常释放。Continue 的本次待确认错误保留已保存设置。占槽 await 抛错不证明事务未提交；即使没有实际提交，也按未知结果保留本次预占，由既有 expiresAt 过期规则处理，不用缺失查询猜测提交结果。prepare 的确定拒绝、CAS 明确未命中仍使用原清理路径。
6. 启动表是独立内部投递日志，不新增组织/序列外键；当前 owner 的联表校验限制读取与投递。序列删除同批清理记录，组织沿用原删除流程，提交删除后由 orphan 清理删除无主记录，避免前置清理造成请求丢失。恢复队列以 lastAttemptAt 轮转，持续失败的旧批次不会永久挡住后续项。

## 尚未关闭

本协议针对具有持久启动记录的新请求。没有该记录的旧 raw claim 沿用原解析策略；没有凭空恢复旧 payload。根任务终态不能证明旧后代已经结束，本批没有实现取消或完整后代互斥。其它内容写入和素材事件归属、发送重试和邮件一致性、Continue 完整设置并发、独立 Update all 预检、独立 AnalyzeScript CLI 仍待后续治理。

未执行真实 Cloudflare 多实例、durable restart/replay、浏览器、模型供应商、邮件或钱包最终结算验收；没有推送或部署。五份冻结 inventory 的 1,219 项仍全部保持 pending，本批不批准该清单或宣布 P3 完成。
