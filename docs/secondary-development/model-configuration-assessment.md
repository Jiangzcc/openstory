# 管理员默认模型配置

更新：2026-11-16。本文记录现行二开契约；逐批实施、运行日志和截图见末尾历史入口。

## 来源、目标与范围

- **上游已有**：模型目录、用户选择器、管理权限、供应商适配、组织钱包和工作流框架。
- **二开已实现**：管理员维护默认推荐及内部辅助模型，保存到现有配置存储，并接入创建和执行快照。
- **业务动机**：运营方可调整默认模型组合，不必改代码，也不必逐个修改用户作品。
- **未实施**：人民币销售计价、汇率核算和全面禁止 BYOK。商业范围以 [规则确认单](confirmation.md) 为准。

配置调整不新增供应商能力，不提供任意模型 ID 绕过目录或权限的入口。

## 管理入口与配置项

入口为“管理后台 → 模型配置 → 默认与内部模型”，URL 为 `/admin/models?tab=defaults`；沿用中英切换。

| 分组         | 可配置项                                                                                                      |
| ------------ | ------------------------------------------------------------------------------------------------------------- |
| 通用默认     | 分析、图片、视频、音乐、新建序列视频                                                                          |
| Turbo 推荐   | 分析、图片、视频、音乐                                                                                        |
| Quality 推荐 | 分析、图片、视频、音乐                                                                                        |
| 内部步骤     | 拆场景、图片理解、Studio 提示词草拟、提示词精简、风格推荐、序列封面、分镜草图、上传视频人物检查、助手视频理解 |

共 22 项。撤销修改和恢复代码默认只改变表单，保存后才持久化。
候选来自相应目录及有效渠道绑定，按场景校验能力；图片理解要求视觉能力，视频理解仍限已有原生 Google 适配。
新建视频保留原入口的供应商可用性及比例检查。

## 权限、存储与保存

- 管理读取和保存均经 `systemAdminMiddleware`；组织 owner/admin 不自动获得平台配置权限。
- 使用现有 `app_metadata` 的 `secondary-development:model-configuration:v1` JSON，不增加专用表或迁移。
- 普通 ScopedDb 只暴露读取，系统管理员范围才暴露保存；公开读取仅返回模型 ID，支持匿名创作界面。
- 配置及目录读取使用现有主库边界；存储损坏或不满足当前规则时明确失败，不吞错。
- 未保存配置时采用代码默认；部分字段未提供时补齐默认。不可用的自定义文本覆盖回到该槽代码默认。
- 已存图片模型身份可保持可读；新增选择和执行仍各自校验可用性，避免失效绑定拖垮整个配置页。
- 单管理员、管理配置不并发是当前前提；文本和图片渠道使用普通保存，不维护 revision/CAS 或草稿过期协调。

## 生效与任务快照

用户显式选择、已有作品和产物保存的模型优先；管理员保存不批量重写这些值。
没有显式覆盖的新创作、Studio 和助手采用当前配置，Turbo/Quality 使用相应推荐。
创建入口先补齐未提供的模型，再做原 schema 校验；内部模型由服务端决定。

可信准备阶段加载完整 `ModelRuntimeConfiguration`，包含默认/内部槽位及文本、图片路由。
服务器决定的快照覆盖请求 body 的同名字段；父子任务及失败处理继承同一份配置。
运行中不重读当前管理员配置；管理员渠道凭证通过冻结的不可变 ID 在实际调用步骤中解析。
组织及原生供应商凭证仍沿用各自现有解析规则，不能把渠道 ID 契约扩大到全部凭证。
合法省略运行配置时使用代码默认和空路由，不在回放时读取最新 D1 配置。
现行路由 wire 为文本 v1、图片 v2 字典格式；旧平铺数组及图片 v1 已退役。

费用使用实际模型、凭证来源和 via。LLM 前置预检仍有上游近似估算，不等于逐模型精确报价。
图片渠道价卡、预占和实际数量计费见 [图片渠道](image-channels.md)，不是人民币钱包改造。

## 实现职责与升级检查

| 位置                                                                       | 职责                             |
| -------------------------------------------------------------------------- | -------------------------------- |
| `src/models/model-configuration.ts`                                        | 配置槽位、代码默认、目录能力校验 |
| `src/models/model-configuration.fn.ts`、`server/db/model-configuration.ts` | 管理权限、公开读取、配置持久化   |
| `src/models/ui/admin-model-configuration.tsx`                              | 表单及保存交互                   |
| `src/models/model-runtime-configuration.ts`、`workflow-*-model-routing.ts` | 运行配置与紧凑 wire 编解码       |
| 工作流 trigger/base/child、各领域调用点                                    | 可信快照传递及实际执行桥接       |

升级时检查目录 ID/能力、创建 schema、推荐值消费方、ScopedDb 边界、父子 payload 和辅助调用的计费位置。
新辅助步骤增加显式槽位并遵守快照，不在静态模型目录或页面加入运行时读取。
更细的结构契约见 [模型配置架构](../architecture/model-configuration.md)。
