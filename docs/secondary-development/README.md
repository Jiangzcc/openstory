## 1. 已确认的目标与范围

- 在 OpenStory 开源项目上二次开发，`develop` 承载本项目的二开改动。
- 面向多个租户提供服务，完整复用上游 Organization、成员权限与共享钱包；取消每用户独立人民币余额，不因旧规划增加个人钱包限制。
- 界面默认简体中文，支持切换英文；语言记忆和翻译接入已实现，实际覆盖与验收边界见国际化实施记录。
- 兑换充值复用项目自带兑换卡，面额、兑换次数、有效期及管理方式沿用现有实现，不再安排卡密商业改造。
- 现有钱包及兑换卡保留实际币种，不安排人民币钱包迁移；人民币模型售价及成本核算仍为未实施规划，与现有钱包的衔接另行设计。
- 保留上游已有 Stripe，不新增在线支付渠道。
- 第三方通过本平台签发的 API Key 直接调用模型暂不纳入首期，未来可能扩展；不因此删除或禁用上游已有的创作 API/MCP。
- 接入包括 fal、OpenRouter 在内的外部模型服务，接入范围可以继续扩展。
- 通过平台收费与供应商成本之间的差额盈利。
- 商业规划不允许用户自带供应商密钥（BYOK），拟由运营方统一提供凭证并按平台余额消费；入口、调用链及结算改造尚未实施，当前组织凭证优先规则保留。
- 允许访问外部 AI 服务；不以完全离线模型部署为前提。
- 分析、设计和交付必须区分上游实现与二开实现。

用户已明确纠正为公网部署，并允许使用 Cloudflare 的部分能力。此前内网独立部署讨论仅保留为历史探索；具体使用哪些 Cloudflare 服务、哪些自建及数据放置仍待技术评估，不把全面运行时迁移或全部 Cloudflare 托管当成已定方案。

## 4. 收费闭环设计建议（尚未实现）

建议围绕如下业务闭环拆分职责，继续复用已有钱包与工作流基础：

1. **充值（已有能力复用）**：沿用现有兑换卡及组织钱包，保留 Stripe；不新增发卡或售卡后台，不改变面额、次数或有效期。兑换事件不能直接当作实际收款。
2. **报价**：根据接入渠道、具体模型、输入/输出单位和任务规格，确定用户价格规则与版本。
3. **预占**：按用户报价冻结可用余额。不能按供应商成本预占，再按更高售价结算。
4. **调用**：服务端解析租户上下文和平台凭证，记录所选渠道；所有重试和轮询沿用该渠道及任务身份。
5. **结算**：按锁定的收费规则、实际有效用量和幂等键确认消费，同时记录供应商成本及其估算/确认状态。
6. **释放与核对**：释放未消费的预占，核对支付与上游账单；供应商成本变化不能直接覆盖用户销售价格或已完成账单。

上述步骤区分现有充值能力和后续销售结算规划，不代表已经存在同名表、字段或 Service。人民币模型销售单价与现有组织钱包的衔接尚待设计；供应商成本保留原始币种，版本化汇率用于人民币成本核算。本次不要求钱包或兑换卡币种迁移，也没有实现新的汇率、计价倍率或结算行为。

建议分清以下记录，而不强制现在建立四张新表：

| 业务记录      | 回答的问题                                                                     |
| ------------- | ------------------------------------------------------------------------------ |
| 收款记录      | 客户实际付了多少，是否已经收到款项？与兑换额度分开理解，本次不新增售卡登记后台 |
| 钱包账本      | 哪个租户入账或消费了多少，是否重复处理？                                       |
| 上游用量/成本 | 哪个渠道的哪个任务产生了什么用量，成本是否最终确认？                           |
| 用户销售账单  | 本次任务适用哪个价格版本，客户应付多少？                                       |

例如，上游成本 1、用户消费 1.3，调用差价为 0.3；它不是净利润。具体售价可固定、按单位或按规则计算，不能在用户未确定计价方式前只修改一个全局常量。

### 人民币模型售价与供应商成本（仍为规划）

已取消个人独立人民币余额和卡密商业改造；现有组织钱包及兑换卡继续按实际币种工作。保留的模型售价与成本核算规划如下：

- 按模型/规格维护人民币销售单价，任务锁定价格；售价如何衔接现有钱包的预占、扣费和消费记录尚待设计，不能据此将组织钱包改称人民币钱包。
- 供应商保留原币种用量与成本，适用汇率及版本/时间用于人民币成本核算；供应商预估与实际账单继续区分。
- 模型调用金额可能小于一分钱，销售计价与成本换算需明确精度和舍入规则；本次不重定义钱包金额类型或存量账本。
- 上游 `src/billing/money.ts` 的 Microdollars 明确表示微美元，不能只替换货币符号或将旧值直接解释为人民币。
- 本次不查询或设定实际 USD/CNY 汇率、加价比例或面额档位，不执行币种迁移。

### 必须保留或补齐的行为

- 一笔充值确认重试多次只入账一次；浏览器返回成功页不能单独作为入账依据。
- 同一租户并发任务不能重复占用同一份可用余额；工作流重放不能重复扣费。
- 报价、预占、结算使用同一价格语义与版本；任务中途调价不能使同一任务前后使用不同规则。
- 失败时区分上游是否已经收费；按确定的产品规则处理费用，释放未用预占，不能假设所有失败都无成本。
- 供应商成本未知或余额结算不足时进入可追踪异常；不能把告警日志当作商业账单已经结清。
- 成本对账比较供应商成本；不得将用户含差价的扣费与供应商原价直接比较。现有 fal 核对路径涉及交易元数据，改价时需一并验证。
- 不向前端暴露平台上游密钥；租户额度、并发和速率限制与供应商账户额度分别治理。
- 租户隔离验收覆盖网页、RPC、REST、MCP、后台任务、文件与管理端。
