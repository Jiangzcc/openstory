# Model configuration

The secondary-development admin page at `/admin/models` has URL-addressable tabs for default recommendations/internal helper models (`tab=defaults`), administrator-owned text channels (`tab=text-channels`), and image channels (`tab=image-channels`). The upstream catalogs, adapters, user pickers and generation stages remain the base implementation. Built-in text models prefer applicable organization credentials, then an administrator binding, then the existing platform fallback.

## Authoritative settings

src/models/model-configuration.ts defines supported slots, original defaults and capability validation. The model-domain DB module stores one JSON record under secondary-development:model-configuration:v1 in the existing app_metadata table. A read scope has no write method; only the system-admin scope exposes save. Both administrative server functions enforce systemAdminMiddleware. The public read returns model identifiers only, so anonymous composers can obtain defaults without accessing secrets.

Creation fills omitted models before the existing schema validates them. Existing explicit choices and stored asset/sequence models remain authoritative. Mode recommendations, new-sequence video recommendations and generic operation defaults are separate slots because upstream gave them distinct behavior. Provider availability and aspect-ratio checks still apply.

An anonymous Enhance click opens sign-in and preserves its intent before checking model readiness. Authenticated enhancement and post-login intent recovery still wait for the model settings and catalog validation before making a model request.

The form scroll container is positioned with relative so Base UI Select's absolutely positioned hidden inputs stay inside it. Without that containing block, the inputs position against the outer main and extend the document's scroll area, creating a second scrollbar.

## Consistency and session changes

Global default-model reads, channel metadata reads, current-catalog validation and encrypted credential lookups use the existing D1 `onPrimary` boundary. An older concurrent HTTP response can replace a browser bookmark after a newer configuration save; configuration routing must therefore read the primary rather than depend on that bookmark. This also covers anonymous defaults and server-side workflow snapshot creation. Already-started runs still resolve their immutable credential IDs and retain their original routing snapshots.

Administrative save callbacks and image-channel candidate synchronization also capture the cached session Query, user ID and session ID. Clearing or rejecting the session invalidates that generation. A delayed response from a previous sign-in cannot repopulate model/channel caches or finish the current editor. This guard is scoped to the QueryClient and holds no process-global identity state.

## Configured text models

`src/models/text-channels.ts` defines channels and model bindings separately from the default slots. A binding names a built-in text model or a `custom:` identifier, its channel and exact upstream model ID, declared capabilities, token limits and supplier USD rates. The channel protocol is either `openai-chat-completions` or `openai-responses`; the administrator selects it explicitly. Existing saved channels keep Chat Completions. A saved binding does not add native provider APIs. Enabled built-in bindings must preserve structured output, tools and any built-in vision capability.

Each text channel also has an optional `User-Agent` in its administrator editor. Blank or absent values use the product identity `OpenStory/0.1.0`, including legacy configurations and queued snapshots without that field. Omitting the field from an update preserves the saved override, including when rotating the API key; an explicit empty string restores the default. Overrides accept at most 256 printable ASCII characters, keeping the worst-case workflow snapshot within its existing size budget. Both compatible SDK protocols and model discovery send this identity; no arbitrary header or credential override is exposed. Fresh execution snapshots freeze the effective value, and workflow packing keeps it in the complete channel identity. Later channel edits do not alter an existing snapshot. Public model catalogs omit this administrator-only setting.

`getTextModelCatalogFn` projects active routing entries into a public catalog without channel IDs, base URLs, upstream model IDs or credential references. `mergeTextModelCatalog` overlays those entries on the built-in registry and adds custom models. Default-slot reads and saves use the same catalog for capability checks. Native video-understanding slots (`talentVideo`, `watchClip`) remain limited to existing native Gemini models.

A route participates only when both its binding and channel are enabled and the channel has a credential reference. This is routing availability, not global model enable/disable governance: disabling a built-in binding returns later calls to its original route, while a custom model without a matching active route is unavailable. Reading saved defaults discards an unavailable custom override and restores that slot's code default; this is configuration resolution, not recovery from a failed bound call.

Administrator channel reads/saves, binding saves and candidate discovery use `systemAdminMiddleware`. Discovery issues only `GET <baseUrl>/models` with the stored credential, returns filtered candidates, and never saves or enables a binding. Choosing a candidate opens a disabled draft whose capabilities, limits and rates must be supplied explicitly. New API endpoint metadata is matched against the selected protocol (`openai` for Chat Completions, `openai-response` for Responses); a plain OpenAI catalog without endpoint metadata remains usable. Input-format guidance lives in placeholders, while credential rules, capabilities and USD cost units stay visible. See the [text-channel implementation record](../secondary-development/text-channels.md).

Administrator default-model drafts validate only the edited slot while the form is being changed. This lets an administrator replace several unavailable models one at a time without discarding other draft values. Saving still validates the complete form against the current catalog on both client and server.

## Durable runs

The request-side trigger loads `ModelRuntimeConfiguration`: default/helper slots plus the active `textModelRouting` snapshot. Root and child triggers pack this into `WorkflowModelConfiguration` on the payload: channel details are stored once per complete channel identity and models refer to a channel index. Catalog descriptions and vendor labels stay out of the workflow wire format; model names, routing, capabilities, limits, rates and credential references remain frozen. `toWorkflowScopedDb` unpacks the execution routes before use. The versioned decoder also accepts the earlier route-array payloads, so already queued runs keep their recorded configuration. A trusted server-side `options.modelConfiguration` carries an existing run's snapshot when it starts more work; `body.modelConfiguration` is always overwritten. `spawnAndAwaitChild` requires the parent's snapshot. The base workflow exposes it as `scopedDb.models` for execution and failure handling. A legacy payload uses code defaults and an empty routing snapshot, never the current configuration at replay time.

Helper model selection, credential lookup, output-token limits and final billing must use the model resolved for that operation. Model configuration is not a new live-read hatch. Do not put secrets in the payload or replace a snapshot with a later D1 read.

Request-side shot-preview redraws load the complete runtime configuration, including text routes needed by content-prompt softening; previews spawned inside a run inherit that run's snapshot. Scene-split output budgets are calculated after each call resolves its credential: compatible calls use the bound route's context/output limits, while existing gateways and native vias retain the built-in limits. Scenes and bibles keep their 65% context budget; shot lists keep the full-context budget, always capped by the selected model's maximum output.

Channel metadata and encrypted credentials are separate records in `app_metadata`. Credentials reuse AES-256-GCM encryption and are write-only through the administrative API: reads expose `hasKey`/`keyHint` and a credential ID, never the key or ciphertext. The routing snapshot contains that immutable ID, endpoint, upstream model, capabilities, limits and rates. The credentials hatch decrypts the referenced record only when needed. Rotation creates a new credential record and retains the old one so an existing run keeps its original route and credential; changing a channel base URL requires a new key. Protocol edits affect only new snapshots: existing runs keep the previously selected Chat Completions or Responses API. The channel URL length limit also applies after URL normalization and percent encoding, preventing a short Unicode path from expanding beyond the configured URL budget. Request-side model catalogs and administrator metadata are not packed or truncated.

## Deliberate limits

The text extension adds explicit administrator-owned Chat Completions / Responses bindings and custom text identities. The text extension does not itself add image/video/audio adapters, global model enable/disable governance, CNY sales prices or cross-device user preferences. Administrator image channels are a separate extension described below. Speech synthesis and voice conversion retain their one-model adapter contracts.

For a built-in text model, applicable organization credentials (`source: 'organization'`) take precedence: matching native xAI/Google, mapped LLMTR, OpenRouter, then fal. If none is usable, an active administrator binding resolves as `source: 'platform', via: 'compatible'`; without a binding, the existing platform fallback applies. A `custom:` model requires its administrator binding and does not consult organization gateways. Unavailable referenced credentials, capability failures and provider errors on that binding fail the call without switching to OpenRouter, fal, a native provider or another channel. Existing region recovery depends on the actual resolved credential, not the presence of a binding: organization/native calls retain it even with a dormant binding, while actual compatible calls remain pinned. Durable retries re-resolve the target credential inside the call step; a compatible fallback target uses its captured rates and platform billing source. Native video Files calls resolve `resolveOptionalKey('google')` directly, using organization Google credentials before platform Google credentials. Text bindings and organization OpenRouter/fal keys cannot capture a Files call.

Configured input/output rates are supplier USD estimates per million tokens. `configuredTextCostUsd` uses reported token counts and the snapshotted rates; this is not a verified supplier invoice or a CNY retail price. LLM preflight estimates remain the upstream coarse approximation. Credit checks and reservations use the resolved credential sources of the text models the operation will call, including internal helper models; an unrelated organization key does not cover a platform text call. Confirmed organization authentication failures carry safe credential-source metadata through the durable error string. Both durable LLM helpers attach that metadata only to provider construction, iteration and fully drained RUN_ERROR failures, using the key resolved for that attempt. Image-download and realtime-publish failures keep their original errors. Platform failures and errors without a confirmed organization source do not invalidate any organization provider key. No currency conversion, retail markup or RMB wallet migration is implemented here.

The original defaults implementation record is [model-configuration-assessment.md](../secondary-development/model-configuration-assessment.md); the text-channel extension and its verification boundary are recorded separately in [text-channels.md](../secondary-development/text-channels.md).

## Administrator image channels (2026-11-06)

The image-channel tab at `/admin/models?tab=image-channels` manages platform-owned OpenAI Images channels, explicit built-in bindings or stable custom-image: identities, operation-specific upstream bindings, verified scalar parameter capabilities, and configurable USD per-image price cards. Public catalogs omit endpoints, credentials, upstream identities and supplier costs. Configuration and immutable encrypted ULID credential references use independent app_metadata namespaces with primary reads and revision/CAS.

An active image binding overrides that built-in image model’s fal/native route while retaining its logical ID, name, rank and history; catalog merging replaces the entry rather than duplicating it. Upstream generation/edit IDs remain separate fields. Unlike text credential priority, an image binding is platform-owned and is not bypassed by an organization key. Missing verified operations, capabilities or prices fail closed. Disabling the built-in binding or its channel restores the original route for new tasks; disabling a custom identity leaves it unavailable. Old runs retain their captured bindings. Reading stored defaults preserves recognized built-in and custom image identities even when a current binding is unavailable, so that binding cannot break unrelated model settings or the admin page. New default saves still require a selectable model; execution validates the captured operation and never treats readability as permission to fall back. Image slots do not reinsert a rejected code default after catalog validation. A hidden upstream default remains eligible for its own slot only when its effective route passes the same availability, operation and price checks.

ModelRuntimeConfiguration carries imageModelRouting; its version 2 workflow codec deduplicates channels, parameter sets and price-card sets, and copies their nested settings. It continues to decode version 1 and legacy array payloads. Active image routing has a 256 KiB UTF-8 budget, checked before saving a channel/model and again when packing a trigger; oversized settings cannot be persisted as active execution snapshots. Disabled models are outside that budget so an administrator can recover an oversized configuration. Parents and children retain the same route and price. Image entrypoints load configuration once before pricing and triggering, including when a built-in is unbound. Studio enforces reference and channel-field capabilities at this server boundary because the static transport schema cannot know whether an administrator has bound a built-in. The credentials hatch resolves only the captured credential ID. Built-in image builders retain their narrow type, while runtime validation distinguishes a recognizable historical ID from an executable configured model.

For a single-shot still request, prepareShotImageGeneration returns a server-only bundle containing the existing workflow payload, the captured ModelRuntimeConfiguration and the configured image quote. The credit check and the later claim-owned reservation reuse that quote. prepareShotImageWorkflowInput remains a payload-only facade for batch and stale-update callers. The queued payload retains its existing fields; the image workflow independently reconstructs execution parameters and pricing from the captured configuration. Claim deduplication, reservation keys and trigger-failure release remain in the single-shot service.

Configured channels are platform spend regardless of unrelated organization keys. Price resolution and execution share parameter/default/size selection; unavailable operations, reference combinations, masks, parameters or prices fail before supplier spend. Generation and R2 storage stay in one step, then use the existing credit-deduction and claim sequence. Stable attempt records prevent automatic resubmission after an unknown outcome and recover already-stored results before a new balance check. A separate retryable record step persists the small stored result; a record-write retry never repeats the supplier generation. The existing coarse text preflight remains unchanged. See [image channel implementation](../secondary-development/image-channels.md) for operation and verification limits.

The 2026-11-07 review repair keeps configured parameters and per-image wallet precision on shared client-safe contracts. Enabled saves reject parameters the adapter cannot execute and positive sales rates that cannot be represented as integer microdollars; historical settings remain readable for correction or disabling. Quotes, reservations and execution use the same resolution, and partial-output charges multiply the integer unit rate by the delivered count. Sequence resolution controls derive configured tiers from the current image catalog instead of silently replacing them with the code default. See [image channel review repairs](../secondary-development/image-channel-review-fixes.md).

Studio prompt-length recommendations follow the model's logical identity, including a built-in identity with an administrator channel binding. GPT Image 2.5 retains the catalog's 32,000-character reference and Qwen Image 2 Pro retains its 2,000-character reference. These are advisory character counts, not token counts or provider-verified hard limits; custom-image identities without a catalog reference show only the entered count. Configured image estimates share the composer's bottom-right cost position with built-in models. The compact total uses the prepared estimate without multiplying the image count again, preserves USD and microdollar precision, and has no hover details. Configuration errors remain above the prompt, independently of the cost-visibility preference.
