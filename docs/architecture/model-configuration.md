# Model configuration

The secondary-development admin page at `/admin/models` has separate tabs for default recommendations/internal helper models and administrator-owned text channels. The upstream catalogs, adapters, user pickers and generation stages remain the base implementation. Built-in text models prefer applicable team credentials, then an administrator binding, then the existing platform fallback.

## Authoritative settings

src/models/model-configuration.ts defines supported slots, original defaults and capability validation. The model-domain DB module stores one JSON record under secondary-development:model-configuration:v1 in the existing app_metadata table. A read scope has no write method; only the system-admin scope exposes save. Both administrative server functions enforce systemAdminMiddleware. The public read returns model identifiers only, so anonymous composers can obtain defaults without accessing secrets.

Creation fills omitted models before the existing schema validates them. Existing explicit choices and stored asset/sequence models remain authoritative. Mode recommendations, new-sequence video recommendations and generic operation defaults are separate slots because upstream gave them distinct behavior. Provider availability and aspect-ratio checks still apply.

The form scroll container is positioned with relative so Base UI Select's absolutely positioned hidden inputs stay inside it. Without that containing block, the inputs position against the outer main and extend the document's scroll area, creating a second scrollbar.

## Configured text models

`src/models/text-channels.ts` defines channels and model bindings separately from the default slots. A binding names a built-in text model or a `custom:` identifier, its channel and exact upstream model ID, declared capabilities, token limits and supplier USD rates. The channel protocol is either `openai-chat-completions` or `openai-responses`; the administrator selects it explicitly. Existing saved channels keep Chat Completions. A saved binding does not add native provider APIs. Enabled built-in bindings must preserve structured output, tools and any built-in vision capability.

`getTextModelCatalogFn` projects active routing entries into a public catalog without channel IDs, base URLs, upstream model IDs or credential references. `mergeTextModelCatalog` overlays those entries on the built-in registry and adds custom models. Default-slot reads and saves use the same catalog for capability checks. Native video-understanding slots (`talentVideo`, `watchClip`) remain limited to existing native Gemini models.

A route participates only when both its binding and channel are enabled and the channel has a credential reference. This is routing availability, not global model enable/disable governance: disabling a built-in binding returns later calls to its original route, while a custom model without a matching active route is unavailable. Reading saved defaults discards an unavailable custom override and restores that slot's code default; this is configuration resolution, not recovery from a failed bound call.

Administrator channel reads/saves, binding saves and candidate discovery use `systemAdminMiddleware`. Discovery issues only `GET <baseUrl>/models` with the stored credential, returns filtered candidates, and never saves or enables a binding. Choosing a candidate opens a disabled draft whose capabilities, limits and rates must be supplied explicitly. New API endpoint metadata is matched against the selected protocol (`openai` for Chat Completions, `openai-response` for Responses); a plain OpenAI catalog without endpoint metadata remains usable. Input-format guidance lives in placeholders, while credential rules, capabilities and USD cost units stay visible. See the [text-channel implementation record](../secondary-development/text-channels.md).

Administrator default-model drafts validate only the edited slot while the form is being changed. This lets an administrator replace several unavailable models one at a time without discarding other draft values. Saving still validates the complete form against the current catalog on both client and server.

## Durable runs

The request-side trigger loads `ModelRuntimeConfiguration`: default/helper slots plus the active `textModelRouting` snapshot. Root and child triggers pack this into `WorkflowModelConfiguration` on the payload: channel details are stored once per complete channel identity and models refer to a channel index. Catalog descriptions and vendor labels stay out of the workflow wire format; model names, routing, capabilities, limits, rates and credential references remain frozen. `toWorkflowScopedDb` unpacks the execution routes before use. The versioned decoder also accepts the earlier route-array payloads, so already queued runs keep their recorded configuration. A trusted server-side `options.modelConfiguration` carries an existing run's snapshot when it starts more work; `body.modelConfiguration` is always overwritten. `spawnAndAwaitChild` requires the parent's snapshot. The base workflow exposes it as `scopedDb.models` for execution and failure handling. A legacy payload uses code defaults and an empty routing snapshot, never the current configuration at replay time.

Helper model selection, credential lookup, output-token limits and final billing must use the model resolved for that operation. Model configuration is not a new live-read hatch. Do not put secrets in the payload or replace a snapshot with a later D1 read.

Request-side shot-preview redraws load the complete runtime configuration, including text routes needed by content-prompt softening; previews spawned inside a run inherit that run's snapshot. Scene-split output budgets are calculated after each call resolves its credential: compatible calls use the bound route's context/output limits, while existing gateways and native vias retain the built-in limits. Scenes and bibles keep their 65% context budget; shot lists keep the full-context budget, always capped by the selected model's maximum output.

Channel metadata and encrypted credentials are separate records in `app_metadata`. Credentials reuse AES-256-GCM encryption and are write-only through the administrative API: reads expose `hasKey`/`keyHint` and a credential ID, never the key or ciphertext. The routing snapshot contains that immutable ID, endpoint, upstream model, capabilities, limits and rates. The credentials hatch decrypts the referenced record only when needed. Rotation creates a new credential record and retains the old one so an existing run keeps its original route and credential; changing a channel base URL requires a new key. Protocol edits affect only new snapshots: existing runs keep the previously selected Chat Completions or Responses API. The channel URL length limit also applies after URL normalization and percent encoding, preventing a short Unicode path from expanding beyond the configured URL budget. Request-side model catalogs and administrator metadata are not packed or truncated.

## Deliberate limits

The text extension adds explicit administrator-owned Chat Completions / Responses bindings and custom text identities. It does not add arbitrary image/video/audio adapters, global model enable/disable governance, CNY sales prices or cross-device user preferences. Speech synthesis and voice conversion retain their one-model adapter contracts.

For a built-in text model, applicable team credentials take precedence: matching native xAI/Google, mapped LLMTR, OpenRouter, then fal. If none is usable, an active administrator binding resolves as `source: 'platform', via: 'compatible'`; without a binding, the existing platform fallback applies. A `custom:` model requires its administrator binding and does not consult team gateways. Unavailable referenced credentials, capability failures and provider errors on that binding fail the call without switching to OpenRouter, fal, a native provider or another channel. Unbound models retain the existing content/region recovery strategy. Native video Files calls resolve `resolveOptionalKey('google')` directly, using team Google credentials before platform Google credentials. Text bindings and team OpenRouter/fal keys cannot capture a Files call.

Configured input/output rates are supplier USD estimates per million tokens. `configuredTextCostUsd` uses reported token counts and the snapshotted rates; this is not a verified supplier invoice or a CNY retail price. LLM preflight estimates remain the upstream coarse approximation. Credit checks and reservations use the resolved credential sources of the text models the operation will call, including internal helper models; an unrelated team key does not cover a platform text call. Confirmed team authentication failures carry safe credential-source metadata through the durable error string. Platform failures and errors without a confirmed team source do not invalidate any team provider key. No currency conversion, retail markup or RMB wallet migration is implemented here.
